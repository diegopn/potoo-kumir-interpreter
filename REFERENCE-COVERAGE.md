# Kumir reference coverage

This crate targets the versioned Kumir 2.1.0-rc11 manuals. It exposes classic and high-grade profiles and implements a text parser, runtime, CLI, and host interfaces; it does not recreate Kumir's graphical IDE.

| Reference area | Implemented behavior | Boundary |
| --- | --- | --- |
| Core language | Program structure, declarations, scalar and table types, expressions, assignment, input/output, assertions and contracts, branches, loops, user algorithms, recursion, and `арг` / `рез` / `аргрез` parameter modes | Ordinary variables and table elements begin undefined; reading one before assignment fails at runtime. Body declarations become available at their source position. Flow-sensitive static definite-assignment analysis is not implemented. |
| Classic and high-grade profiles | Separate standard-library inventories and core syntax; the high-grade profile includes the documented `Строки` library | Other Kumir editions and releases are outside this profile. |
| Standard libraries | Documented lexical conversion, math, string, file, and system routines; file operations are routed through `FileHost` | Paths, permissions, encoding, file handles, and cleanup after runtime errors belong to the host. |
| Executor modules | Robot, Draftsman, Grasshopper, Isometric Robot, Turtle, Keyboard, Painter, Vodoley, and Complex Numbers; calls preserve module, normalized name, typed arguments, and input/result modes | Drawing, field/vessel state, keyboard events, and actor interaction require `ModuleHost`; the CLI does not supply these services. |
| Static actor signatures | Known command names, arities, input types, output types, and function return types are checked; host-returned function and output values are checked at runtime | The Robot manual gives contradictory result descriptions for `@@верхняя буква`, `@@нижняя буква`, `@@температура`, and `@@радиация`; these result types remain unspecified. |
| Teacher-only routines | Teacher query signatures documented for Robot, Draftsman, and Isometric Robot are represented and rejected in the default student context; `Interpreter::with_execution_context(ExecutionContext::HiddenTeacherCode)` enables them for hidden teacher code | The embedding application must select the correct source section context when executing visible or hidden code. |
| Module name collisions | Each call resolves to an enabled module and documented routine | If multiple enabled modules provide an identical command spelling, declaration order controls dispatch; the manuals do not define this case. |
